# IAM & SOC Relational Data Model Specification

## 1. Schema Tables Overview

### Core Workforce & RBAC
- `workforce_identities`: Enterprise staff records, lifecycle states, MFA status, department, and country assignment.
- `workforce_roles`: Role definitions (e.g., `MLRO`, `TREASURY_MANAGER`, `SECURITY_ADMIN`).
- `workforce_permissions`: Granular resource-action-scope permissions (e.g., `customer:read_pii:NG`, `settlement:approve:amount<10m`).
- `workforce_role_permissions`: Join table binding permissions to roles.
- `workforce_identity_roles`: Active role assignments to workforce identities.

### Sessions, Devices & PAM
- `iam_sessions`: Ephemeral workforce sessions with AAL assurance level, device binding, and activity timestamps.
- `iam_devices`: Device inventory, trust states (`TRUSTED`, `RESTRICTED`, `BLOCKED`), and hardware fingerprints.
- `iam_privileged_access_requests`: JIT elevated privilege requests, justifications, lease duration, and dual approvals.
- `iam_break_glass_events`: Emergency break-glass activations, rationale, TTL, and post-incident review status.

### Security Events & SOC
- `security_events`: Centralized immutable event log with actor, session, IP, action, result, and correlation ID.
- `security_alerts`: Explainable security alerts generated by detection rules.
- `security_incidents`: Formal security incident records with severity, assigned commander, blast radius, and containment state.
- `security_incident_notes`: Timestamped forensic investigation notes.
- `data_export_authorizations`: Audit vault tracking customer PII export requests and approvals.
